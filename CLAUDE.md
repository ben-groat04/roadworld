# City Painter (roadworld)

Photoreal sandbox city builder. UK is only the first region pack, for prototyping; the core must stay region-agnostic (all region-specific values live in `data/regions/<region>/`). Source of truth for decisions: `docs/planning-log.md`. Unreal structure: `docs/unreal-architecture.md`. Docs index: `docs/README.md`.
v0 scope: `docs/v0-brief.md`. Markings reference: `docs/road-marking-rules.md`.

## Layout
- `sim_core/` – engine-agnostic headless C++20 library. No Unreal headers, no GPL/copyleft deps (no CGAL). Clipper2 is the approved geometry lib.
- `tests/` – doctest unit/golden tests. Build: `cmake -S . -B build && cmake --build build && ctest --test-dir build`.
- `prototypes/` – throwaway browser UX test tools (not production code).
- `prototypes/road-draw/src/` – prototype sources split by area; index.html is generated by build.mjs
- `data/` – data-defined lane types, plus region packs (`data/regions/uk/`: road types, marking rules, clearances, units).
- `unreal/` – Unreal 5.8 project and plugin (`unreal/CityPainter/Plugins/`), a thin host for sim_core; command-line build and editor automation in `unreal/tools/` (see its README).
- `tools/` – asset tooling outside the engine (`tools/blender_kit/`: scripted Blender kit meshes).
- `third_party/` – vendored libraries (Clipper2, doctest, nlohmann json); permissive licences only.
- `docs/` – planning docs and design proposals; index in `docs/README.md`, new-session entry point `docs/HANDOFF.md`, research notes in `docs/research/`.

## Rules
- Every player edit is a `cp::Command` executed through `cp::CommandStack`.
- Objects are referenced by stable `cp::Id<Tag>`; IDs are never reused.
- World coordinates are doubles (20 km+ maps).
- Lane graph and junction rules are driving-side agnostic: one setting per save, everything mirrors from it.

## Working style (from the person)
- The main session (Opus) plans, asks questions, reviews and coordinates. **All coding is delegated to subagents**, never written by the main session: Sonnet (`model: sonnet`) by default, Haiku (`model: haiku`) only for trivial mechanical edits (renames, doc tweaks, config one-liners) where a wrong result is obvious and cheap to redo.
- Ask the person for input often on design and UX decisions; keep reversible choices moving.
- **Never end a turn with uncommitted changes**: commit and push at the end of every turn without being asked.
- **Default to parallel agents** split by file/function, each with tight scope and exact function names; continue existing agents via messages instead of spawning new ones for follow-ups.
- **Verify with `node prototypes/road-draw/tools/scene.mjs --check`** (text invariants, ~8 s; needs one-time `npm install` in prototypes/road-draw) rather than screenshot loops; screenshots only for realism judgement.
- **Send the person progress pictures** whenever new visual results exist.
- **The main session never audits screenshots or code itself**: visual and code review go to cold-read Sonnet agents; the main session reads only their reports.
- **New session? Read `docs/HANDOFF.md` first.**
- **Reference claims need opened references.** Any statement about what the reference photos show must name the reference files actually opened; review briefs must require this, and a score based on fewer than two opened references per view must say so (see `docs/README.md`, "Reference claims").
- **Unreal is a single lane**: one agent at a time builds the plugin or runs the editor; queue Unreal work. Prefer the live editor via MCP over cold-start scripts.
- **One git worktree and branch per code agent** (at least its own build dir, CLEAN builds). Merge one agent at a time; run the full suite on both compilers after each merge. After an agent says "N/N pass" in a shared tree, trust only a clean build of the merged state.
- **Watch the usage limit**: at most 3-4 agents at once, finish before starting more, resume an agent with context rather than spawning a new one, stop agents re-sending finished reports, commit WIP before the limit cuts it off.
- **Agents always run in the background** (a failed foreground launch blocks the turn). Every push carries `[skip ci]` until the person asks for CI (last CI-verified commit `1ae80b0`).
- **Research Unreal/plugin/tool facts with agents, never from memory**; verify against `C:\UE_5.8` source.
- **Briefs**: no unbounded absolutes ("as many tiers as needed") without a sanity bound; require agents to look at and judge results and to report what they did NOT verify; render and cold-read every geometry or look change before building on it.
- **Check commits landed** with `git status -sb`, not the exit code.
- **Send the person pictures as files** whenever new visual results exist (they often follow from a phone).
- **Decision split**: road-engineering details are the assistant's (region-data defaults); product direction, scope, purchases, downloads and anything irreversible are the person's.
- **Product framing (11 Oct)**: it is a game; a road placed in the open world must produce everything in the picture via a `world_cover` layer and road-generated content (incl. lighting columns); no hand-dressed look-test levels. Details in `docs/HANDOFF.md` section 1.
- **Reference photos are the target, all the time**: any work that changes what the player sees starts by opening the relevant photos in `docs/reference/` (at least 3 per case where they exist, top-down for layout), noting what was measured in lane widths and naming the files; results are rendered at the same framing and compared item by item; reviews score layout/markings separately from look; "joins up" properties become tests.
