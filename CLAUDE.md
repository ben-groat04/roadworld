# City Painter (roadworld)

Photoreal sandbox city builder. UK is only the first region pack, for prototyping; the core must stay region-agnostic (all region-specific values live in `data/regions/<region>/`). Source of truth for decisions: `docs/planning-log.md`.
v0 scope: `docs/v0-brief.md`. Markings reference: `docs/road-marking-rules.md`.

## Layout
- `sim_core/` – engine-agnostic headless C++20 library. No Unreal headers, no GPL/copyleft deps (no CGAL). Clipper2 is the approved geometry lib.
- `tests/` – doctest unit/golden tests. Build: `cmake -S . -B build && cmake --build build && ctest --test-dir build`.
- `prototypes/` – throwaway browser UX test tools (not production code).
- `prototypes/road-draw/src/` – prototype sources split by area; index.html is generated by build.mjs
- `data/` – data-defined lane types, plus region packs (`data/regions/uk/`: road types, marking rules, clearances, units).
- `docs/` – planning docs and design proposals.

## Rules
- Every player edit is a `cp::Command` executed through `cp::CommandStack`.
- Objects are referenced by stable `cp::Id<Tag>`; IDs are never reused.
- World coordinates are doubles (20 km+ maps).
- Lane graph and junction rules are driving-side agnostic: one setting per save, everything mirrors from it.

## Working style (from the person)
- The main session (Opus) plans, asks questions, reviews and coordinates. **All coding is delegated to subagents**, never written by the main session: Sonnet (`model: sonnet`) by default, Haiku (`model: haiku`) only for trivial mechanical edits (renames, doc tweaks, config one-liners) where a wrong result is obvious and cheap to redo.
- Ask the person for input often on design and UX decisions; keep reversible choices moving.
- **Never end a turn with uncommitted changes**: commit and push at the end of every turn without being asked.
- **Default to parallel agents** split by file/function, each with tight scope and exact function names; continue existing agents via messages instead of spawning new ones for follow-ups.
- **Verify with `node prototypes/road-draw/tools/scene.mjs --check`** (text invariants, ~8 s; needs one-time `npm install` in prototypes/road-draw) rather than screenshot loops; screenshots only for realism judgement.
- **Send the person progress pictures** whenever new visual results exist.
- **The main session never audits screenshots or code itself**: visual and code review go to cold-read Sonnet agents; the main session reads only their reports.
- **New session? Read `docs/HANDOFF.md` first.**
