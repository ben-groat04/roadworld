# City Painter (roadworld)

Photoreal sandbox city builder. UK is only the first region pack, for prototyping; the core must stay region-agnostic (all region-specific values live in `data/regions/<region>/`). Source of truth for decisions: `docs/planning-log.md`. Unreal structure: `docs/unreal-architecture.md`. Docs index: `docs/README.md`.
Scope of the game (milestones M1-M8): `docs/unreal-game-plan.md` (v0 brief `docs/v0-brief.md` is historical). Markings reference: `docs/road-marking-rules.md`.

## Layout
- `sim_core/` – engine-agnostic headless C++20 library. No Unreal headers, no GPL/copyleft deps (no CGAL). Clipper2 is the approved geometry lib.
- `tests/` – doctest unit/golden tests. Build: `cmake -S . -B build && cmake --build build && ctest --test-dir build`.
- `prototypes/` – throwaway browser UX test tools (not production code).
- `prototypes/road-draw/src/` – prototype sources split by area; index.html is generated by build.mjs
- `data/` – data-defined lane types, plus region packs (`data/regions/uk/`: road types, marking rules, clearances, units).
- `unreal/` – Unreal 5.8 project and plugin (`unreal/CityPainter/Plugins/`), a thin host for sim_core; command-line build and editor automation in `unreal/tools/` (see its README).
- `tools/` – asset tooling outside the engine (`tools/blender_kit/`: scripted Blender kit meshes) and the agent-process scripts: `make_brief.mjs`, `check_handin.mjs`, `new_agent_worktree.ps1`, `worktree_status.ps1` (read-only state of every worktree: run it first in a new session); `tools/hooks/` enforcement hooks (below).
- `third_party/` – vendored libraries (Clipper2, doctest, nlohmann json); permissive licences only.
- `docs/` – planning docs and design proposals; index in `docs/README.md`, new-session entry point `docs/HANDOFF.md`, the only queue `docs/QUEUE.md`, prepared task files `docs/tasks/`, research notes `docs/research/`, per-round hand-ins `docs/progress/` (naming in its README), private reference photos `docs/reference/` (gitignored).
- `.claude/` – project settings with the hook wiring; `.claude/state/` (gate log, Unreal lane lock) is per machine and gitignored.
- New worktrees live in `..\roadworld-wt\<name>` (one `build` dir each); scratch in `..\roadworld-scratch\<name>`.

## Rules
- Every player edit is a `cp::Command` executed through `cp::CommandStack`.
- Objects are referenced by stable `cp::Id<Tag>`; IDs are never reused.
- World coordinates are doubles (20 km+ maps).
- Lane graph and junction rules are driving-side agnostic: one setting per save, everything mirrors from it.

## Working rules (read these; the owner has said each of them more than once)
Source of truth for agents: `docs/AGENT_CONTRACT.md` (pasted unchanged into every brief). Templates: `docs/templates/BRIEF.md`, `docs/templates/STATUS.md`. New session? Read `docs/HANDOFF.md` first, then `docs/QUEUE.md` (the only work queue; anything not written there is not queued).

### Hooks enforce part of both gates (`.claude/settings.json`, scripts in `tools/hooks/`, log `.claude/state/gate.log`)
- A launch is refused unless the prompt holds the contract (`make_brief.mjs` output, with `HANDIN_DIR:` and the owner's words) or a `NO-CONTRACT: <reason, 20+ chars>` line (research, merges, read-only checks); an agent cannot hand back or stop until `check_handin.mjs` passes (3 refusals, then `HANDIN_FAILED.txt` in the hand-in folder; read it). Hooks fail open: a log line `FAIL-OPEN` means a gate did not run. They cannot show that a file was really opened or an image really looked at: the gates below stay yours. lock_guard refuses a builder's edit of a locked test, of `LOCKED_TESTS.txt` or of the prior AUDIT.md (contract item 23); a valid `CHECKPOINT.md` lets a builder stop once per round without starting an audit (item 24).

### Two gates (the main session runs both, every time, as a checklist)
**Before sending a brief for visible work** (build it with `node tools/make_brief.mjs <task-file> --round <name>`, create the worktree with `powershell -NoProfile -ExecutionPolicy Bypass -File tools\new_agent_worktree.ps1 <name>`; plain invocation is blocked on this machine, the flag is per-process):
1. At least 3 reference photos named per case, absolute paths in the main checkout (`docs/reference/`); say where none exists. The brief lists EVERY reference file explicitly (photos, screenshots, spec documents), so M is countable.
2. The owner's own words quoted verbatim, with date. Never paraphrase: agents distrust relays.
3. Finish line = "matches the photo", never "these are the whole task"; no time-box in hours. Stop rule: self-audit residual holds only unfixable items, or 3 passes.
4. Hand-in files named: STATUS.md (skipped first), FAULTS.md, COMPARE.md with composites, INDEX.md.
5. Parallelism: list every independent item; start it, or write one line why it waits (Unreal lane, shared file). With fewer than 2 agents running, tell the owner why.
6. Background, own worktree from current main, `[skip ci]`, mute video, download approval, no unbounded absolutes ("as many tiers as needed") without a sanity bound.
**Before accepting a report or telling the owner anything:**
0. Act on any `GATE NOTICE` that appears in your context (FAIL-OPEN, hand-in released after 3 refusals, NO-CONTRACT launches; hook `tools/hooks/gate_notice.mjs`): read the named log lines and `HANDIN_FAILED.txt`, deal with them, then acknowledge EACH item by its own `#n[code]` from the notice: `node tools/hooks/gate_ack.mjs "<n>:<code> ..." "<what was done about it>"` (20+ characters, 4+ words; a blanket ack is gone; the notice repeats until you do). Hand-ins are only accepted when written during that agent's run. `make_brief.mjs` exits 3 and `check_handin.mjs` prints `HOOK CANARY` if `gate.log` shows the hooks are not running: tell the owner at once.
1. Run `node tools/check_handin.mjs <progress-folder>` (`--no-visual` for engine-only work); if it fails, send the list back unread. A report whose `References opened` line is missing, or has N < M without a listed reason, goes back unread, for ALL work with named references, not only visible work. For a round also run it with `--accept`: it fails unless a valid `AUDIT.md` by an agent other than the builder exists. Start the auditor with `node tools/make_brief.mjs <task-file> --audit <progress-folder>`; hooks list every passed hand-in without a valid `AUDIT.md` on every prompt (no ack clears it) and an auditor cannot finish without writing it.
2. Read STATUS first lines for anything skipped, refused or failed; raise it with the owner at once.
3. Check `AUDIT.md` exists in the progress folder and was written by a different agent than the builder (see Main session); if not, start the auditor and do not accept yet. Then, after your own first look (top 3 logged) done before reading AUDIT.md, open the headline images yourself (every time an agent says good, fixed or done), ask "what here would never be built?", and log it in `docs/ACCEPTANCE.md`. Name the reference files you opened. Check that every prior audit item is fixed or open for reason a or b only (STATUS.md "Prior audit items" table).
4. Same-camera before/after must show real movement, else change method, not another tuning round.
5. Update `docs/QUEUE.md` (the only queue: started, reported, new follow-ups, dropped). Commit with `[skip ci]` and push in background (never end a turn with uncommitted changes); check with `git status -sb`, not the exit code. Send pictures as files (the owner often follows from a phone) with your own fault list.

### For every agent (full text: `docs/AGENT_CONTRACT.md`)
- Photos are the target, all the time (and every reference or spec file the brief names is opened, all of them, with `References opened: N of M listed` in STATUS.md): open >=3 per case before designing, name them, measure in lane widths, render at the same framing, compare item by item; layout/markings scored apart from look; "joins up" properties become tests. A claim about what the photos show names the files opened; a score on fewer than 2 opened per view says so.
- Self-audit before anyone else does (owner: agents "should anticipate what the cold read viewer might say and just get round to fixing that also before it actually tries to get its work audited"): up to 3 passes with an own fault list and composites; never mark an item "not done" without having tried it.
- Nothing fails silently: skipped, refused or failed items go in the FIRST lines of the report and STATUS.md.
- Reference photo downloads are pre-approved by the owner (11 Oct, in chat: "If you ever need more reference images go get them"; "yes please allow them to download photos as and when needed"). Any agent may fetch reference photos into `docs/reference/{aerial,street,gsv}/` (private, gitignored, never committed or copied elsewhere; composites go in `docs/reference/_compare/`), logging source URL and content in the reference INDEX. Reference images only: assets, models, textures, tools and anything paid need the owner.
- Own git worktree and branch, own build dir, CLEAN builds (one clean build of the final state; incremental while iterating, gcc while iterating and MSVC once at the end: contract item 25); commit after each verified step; never kill processes you did not start; mute any video; never ask the owner to open Unreal.
- Hand in, in `docs/progress/<round>/`: STATUS.md (first heading "Skipped, refused or failed"), FAULTS.md, COMPARE.md, INDEX.md; run `node tools/check_handin.mjs <folder>` first. Commits carry `[skip ci]`. Do not push or merge unless the brief says so.
- Research Unreal/plugin/tool facts from `C:\UE_5.8` source or docs, never from memory.
- Photos outrank tests, audits and fault lists: a test with no photo measurement or written rule behind it may be rewritten; rebuild a shape from measurements rather than tuning one that came from no photo; never change the design to suit the renderer.

### Main session
- The main session (Opus) plans, asks, reviews and coordinates. **All coding is delegated to subagents**, never written by the main session: Sonnet (`model: sonnet`) by default, Haiku only for trivial mechanical edits (renames, doc tweaks, config one-liners) where a wrong result is obvious and cheap to redo.
- Agents always run in the background (a failed foreground launch blocks the turn). Fresh agent per round, started from the previous STATUS file; resume an agent only for a short follow-up (under about 3 messages). Split work by file/function with exact function names; stop agents re-sending finished reports.
- Run every independent item in parallel, within the limits: at most 3-4 live BUILDERS, finish before starting more; auditors are not capped and never wait for a slot (owner, 11 Oct: "just keep adding them as needed"). **Unreal is a single lane**: one editor or plugin build at a time (code agents may compile in other worktrees meanwhile); prefer the live editor via MCP over cold-start scripts. The owner never opens the editor; an agent exercises every milestone.
- **Builder and auditor are never the same agent** (owner, 11 Oct: "is one earthworks agent creating AND auditing? that's wrong. and elsewhere, that's just an expample"). Every round, of any kind (earthworks, junctions, Unreal, kit, tools, hooks), is: builder (with its own self-audit, which is only preparation) -> a FRESH auditor agent -> the main session. The auditor is part of the round, not optional support, and starts as soon as the hand-in passes the check. It gets the pictures, sections, reference files and the brief's cases; it writes its own fault list BEFORE reading the builder's FAULTS.md or STATUS claims; it also checks that the builder's measuring tools (tests, section sheets, diagnostic views, playtest scripts) show the truth; for each test it names where the expected value came from (photo measurement, written rule, or nothing) and lists tests that pin a fault; it lists the reference files it opened; it writes `AUDIT.md` in the progress folder. Its faults go to a fresh builder, not back to itself. Auditors are strict and the next builder fixes EVERY prior audit item, open only if too pedantic for the owner to notice or the audit's reading is doubtful (owner, 22 Oct: "when you audit, be strict and ensure EVERYTHING gets addressed in a fix. no excuses for not fixing issues unless its like so pedantic i wouldn't notice or you aren't sure the audit is picking things up right"); see `docs/AGENT_CONTRACT.md` item 17. Audits start with a first look and outline overlay (item 18); for rounds whose look is the deliverable (junctions, earthworks, Unreal look) the first look on the headline images is a short separate pass on Opus, while the full audit (measuring, suites, tests) stays on Sonnet (owner, 22 Oct: "I'm more concerned the auditor didn't pick up on what id say is the most obvious visual error"; "Opus for only the important image checks, please not all"). The main session does its own first look on the headline images BEFORE reading the audit and logs its top 3 in `docs/ACCEPTANCE.md`. The main session is the final check, not the first, and does not accept a round with no `AUDIT.md` from a different agent.
- Merge one agent branch at a time; run the full suite on both compilers after each merge; after an agent says "N/N pass" in a shared tree, trust only a clean build of the merged state.
- Verify with `node prototypes/road-draw/tools/scene.mjs --check` (text invariants, ~8 s; one-time `npm install` in prototypes/road-draw) rather than screenshot loops; screenshots only for realism judgement.
- Every push carries `[skip ci]` until the owner asks for CI. Prefer free tools and assets; flag any cost.
- Removing a worktree: first unlink its junction with `cmd /c rmdir <worktree>\docs\reference` (removes the link only), check `docs\reference` in the main checkout still has its files, then `git worktree remove`; never `rm -r`, `rm -rf` or `Remove-Item -Recurse` on a worktree or any folder that may hold a junction (22 Oct 2026 this wiped every private reference photo). After any batch of new reference photos, mirror `docs\reference` to `C:\Users\bgbg0\roadworld-reference-backup` with `robocopy <main>\docs\reference C:\Users\bgbg0\roadworld-reference-backup /MIR` (never the reverse).

- **Workflow rules (23 Oct 2026, owner asked why rounds take so many)**: engineering decisions go in the FIRST brief (structure choice, corner rules, wall versus slope, limits, made from the photos; builders implement, or write why with a photo measurement); one case per round; shape (outline overlay, measurements) and look (judged in Unreal) are accepted apart; no goalpost moves (never raise a test limit or exclude an area; fix the geometry or write BLOCKED). Contract items 19-22.
