# unreal/tools: command-line build and editor automation

**One command, engine installed to first pictures (re-runnable, resumes where it stopped):**
`powershell -NoProfile -ExecutionPolicy Bypass -File unreal\tools\First-Run.ps1 -EngineRoot D:\UE_5.8`
(passing `-EngineRoot` avoids a drive scan; `-LocalDdcPath` (default `C:\UEDDC`), `-MaxParallelActions` (build, default 4) and `-GraphicsAdapter <n>` (editor steps) are forwarded to the steps. Each step's log path is printed before it starts; step timeouts are 120 min.)
(`-DryRun` previews, `-From <step>` / `-Only <step>` / `-Force` override; steps: find-engine, build, environment, textures, level, screenshots; state in `unreal\CityPainter\Saved\first-run-state.json`. On failure it prints the log path and the exact command to re-run that step.)

Only these still need a human:
1. Accept the prerequisites prompt if one is shown.
2. Wait out the first shader compile (10-30+ minutes).
3. Enable the Unreal MCP + All Toolsets plugins and tick Auto Start Server.


Windows PowerShell 5.1. Run from the repo root as `powershell -NoProfile -ExecutionPolicy Bypass -File unreal\tools\<script>`.

| Script | What it does |
|---|---|
| `Find-Unreal.ps1` | Locates UE 5.8 (-EngineRoot, `UE_ROOT`, `LauncherInstalled.dat`, registry, then `<drive>:\UE_5.8` scan) and verifies `Build.bat`, `UnrealEditor-Cmd.exe`, `RunUAT.bat`. Errors clearly on absent or half-installed engines. |
| `Build-Editor.ps1` | Builds `CityPainterEditor Win64 Development` via `Build.bat`, logs to `unreal\CityPainter\Saved\Logs\build-<time>.log`, prints a deduplicated error summary (compiler, linker, UHT, UBT, Build.cs/Target.cs C#). Exit 0 ok, 1 build failed, 2 setup problem. Flags: `-Stream` (echo the log live), `-MaxErrors`, `-Clean`, `-MaxParallelActions <n>` (default 4, passed to UBT), `-LocalDdcPath` (default `C:\UEDDC`, used when env `UE-LocalDataCachePath` is unset), `-GenerateProjectFiles` (opt-in; project files are no longer generated by default, `-SkipGenerate` is accepted and ignored), `-LogPath`. |
| `First-Run.ps1` | Orchestrates all steps below with a resumable state file; see the top of this file. |
| `Run-EditorPython.ps1` | Runs `py\<script>.py` in an unattended editor and summarises the log (`LogPython` lines, tracebacks, module-load failures, crash markers, the script's `CP_PY_RESULT` marker). `-Render` for screenshot runs, default is `-nullrhi`. `-GraphicsAdapter <n>` adds `-graphicsadapter=n` (pick the RTX 4060 over the integrated GPU), `-LocalDdcPath` as for the build, default timeout 60 min. `-ScriptArgs a,b` reaches the script via `cp.script_args()`. |
| `BuildLogParser.ps1` | Parser used by Build-Editor (dot-source it). |
| `py\setup_look_test_level.py` | Creates/updates `/Game/Maps/RoadTest` (Open World template if available) with sky, sun, fog, clouds, post-process, floor, player start and one `CPRoadMeshActor`; assigns `MI_<slot>` surface materials and creates `/Game/Materials/Markings/MI_marking_<colour>`. Idempotent. |
| `py\screenshot_views.py` | Six interchange views (aerial, roundabout oblique + approach, T-junction, slip merge, kerb close-up) into `Saved\Screenshots\look\`. Needs `-Render`. |
| `py\report_environment.py` | Logs engine version, RHI/GPU (from the log), Lumen/VSM/Nanite cvars, plugin probes, and whether `CPRoadMeshActor` loaded. |
| `KNOWN_RISKS.md` | Predicted first-build errors mapped to exact edits. Read it when a build fails. |

## Tests (no engine needed)
```
powershell -NoProfile -ExecutionPolicy Bypass -File unreal\tools\tests\Test-FindUnreal.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File unreal\tools\tests\Test-BuildLogParser.ps1
```
`tests\sample-build.log` is a synthetic log (MSVC, linker, UHT, UBT, C# rules errors); the formats are from memory of
real UE output and should be checked against the first real failing build.

## Writing Python scripts
Copy the pattern in `py\cp_common.py`: `cp.run(main)` prints `CP_PY_RESULT: OK` or `FAIL <reason>` and quits the editor.
Mark any API call not confirmed on 5.8 with `# VERIFY`. Raise `cp.ScriptError("clear message")` to fail loudly.

## Standalone check of CPRoadMeshBuild (no engine)
`Plugins/CityPainterCore/Source/CityPainterSim/Private/Legacy/CPRoadMeshBuild.{h,cpp}` use only the standard library and sim_core, so they compile without Unreal. To re-check after changes: in a throwaway directory OUTSIDE the repo (and not under %TEMP%, MSBuild rejects it) copy the repo's top-level `CMakeLists.txt`, `sim_core`, `tests`, `data`, `third_party`, append
`add_executable(check main.cpp <abs path>/CPRoadMeshBuild.cpp)`, `target_include_directories(check PRIVATE <abs path to Private>)`, `target_link_libraries(check PRIVATE sim_core)` and `/GR- /EHs-c- /W4` options, with a `main.cpp` that does `CreateWorld(); LoadData(); BuildLayout(); BuildRender();` and checks (a) every asphalt triangle has +Z geometric normal `(b-a)x(c-a)` in the output (same index order as sim: counter-clockwise front face), (b) `tile origin (double) + relative float` reproduces an independent double-precision build to < 0.01 cm. Last result (interchange): see the hand-off report of the commit that added it.

## Automated playtest of the game (camera, picking, HUD): `Run-Playtest.ps1`
`powershell -NoProfile -ExecutionPolicy Bypass -File unreal\tools\Run-Playtest.ps1 [-Out <dir>] [-ResX 1600 -ResY 900]` (needs `Build-Editor.ps1` first; about 4 minutes; the editor must not be running).
It starts the game (`UnrealEditor.exe <uproject> /Game/CityPainter/Maps/L_Sandbox -game -CPPlaytest -benchmark -fps=30 -RenderOffscreen ...`; fixed 30 fps time step so the numbers repeat, frame times are wall clock) and `UCPPlaytestDriver` (`Source/CityPainter/Playtest/`) plays a script: Slate mouse and key events (`FCPPlaytestInput`, no OS cursor movement) go through the real viewport, Enhanced Input, controller and pawn: right-drag rotate and pitch (both ways, limits), middle-drag pan at 20 / 400 / 3000 m, wheel zoom (limits, zoom centre), W/A/S/D and arrows, Shift, Q/E, the world edge, 5 pick points (height against the sim, reprojection, HUD text), HUD refresh and click-through, window resize. Output in `<Out>` (default `unreal\CityPainter\Saved\Playtest\latest`): `results.json` (checks with expected / observed / pass, metrics, notes), `done.txt`, `game.log` and the screenshots (HUD included). The script prints the summary; exit code 0 = all passed, 1 = failures, 3 = crash/no results, 124 = timeout.
Extend it in `CPPlaytestScript.cpp`: one `Scenario...(FBuilder&)` function per feature (`View`, `Drag`, `Hold`, `Wait`, `Shot`, `Do` and `Report`), then add the call in `BuildCPPlaytestScript`. Expected values come from the prototype (`prototypes/road-draw/src/scene.js`).
`pie_leak_check.py` (needs the live editor, see below) starts and stops play-in-editor N times and compares actor counts.

## Driving the live editor over MCP (Epic's `ModelContextProtocol` + `AllToolsets` plugins)
Verified on 5.8.3 with this project on 11 Oct 2026.
- **Start the editor so it does not stall**: `UnrealEditor.exe <uproject> /Game/CityPainter/Maps/L_Sandbox -log -unattended -nosplash -NoSound -nosourcecontrol -NoLoadingScreen -windowed -ForceRes -ResX=1280 -ResY=720 -RenderOffscreen` as a background process with a hidden window. WITHOUT `-unattended` the editor sat forever after loading `StallLogSubsystem` (a hidden modal prompt) and never reached the MCP server. Wait for the log line `Starting MCP server on port 8000` (about 1 minute; the first start with cold shaders can take longer). Port and auto start come from `Config/DefaultEditorPerProjectUserSettings.ini` (`-ModelContextProtocolPort=N` overrides).
- **Transport** (`ModelContextProtocolServer.cpp`): plain MCP streamable HTTP at `http://127.0.0.1:8000/mcp`. POST JSON-RPC with `Content-Type: application/json` and `Accept: application/json, text/event-stream`. `initialize` returns an `Mcp-Session-Id` response header; every later request must send it (else HTTP 400) plus `notifications/initialized`. Responses are JSON (or one SSE `data:` frame when progress is requested). Calls run on the game thread, so a long call blocks the editor.
- **Tool search mode is on**: `tools/list` returns only three meta tools: `list_toolsets`, `describe_toolset {toolset_name}` (names, descriptions, input and output schemas) and `call_tool {toolset_name, tool_name, arguments}`. The real tools are inside toolsets. Useful ones: `EditorToolset.EditorAppToolset` (`StartPIE`, `StopPIE`, `IsPIERunning`, `GetCameraTransform`, `SetCameraTransform`, `CaptureViewport` (PNG as base64, needs `captureTransform`), `CaptureEditorImage`, `GetVisibleActors`, `SearchCVars`), `EditorToolset.LogsToolset` (`GetLogEntries {category, pattern, maxEntries}`), `editor_toolset.toolsets.scene.SceneTools` (`find_actors` needs `name`, `tag` and `collision_channels` all present, `load_level`, ...), `editor_toolset.toolsets.actor.ActorTools`, `editor_toolset.toolsets.programmatic.ProgrammaticToolset` (`execute_script`: a restricted Python that can only call other tools; NOT arbitrary editor Python), `AutomationTestToolset` (discover and run automation tests), `SlateInspectorToolset` (snapshot, click, drag, key press on editor widgets by ref), `ConfigSettingsToolset`, `PluginToolset`.
- **What is missing**: no console-command tool and no arbitrary editor Python over MCP (use `Run-EditorPython.ps1` for scripts); no held keys, wheel or pointer positions (Slate `Click`/`Drag` act on widget refs). Continuous input is therefore tested with `Run-Playtest.ps1`, which sends Slate events inside the game.
- **Helper**: `mcp_call.py` (standard library only; run with the engine's Python: `C:\UE_5.8\Engine\Binaries\ThirdParty\Python3\Win64\python.exe`, the machine has none on PATH). `python mcp_call.py tools`, `python mcp_call.py call <tool> '<json>'`, or `from mcp_call import Mcp, call_toolset, capture_viewport`. Example: `call_toolset(m, EDITOR_APP, "StartPIE", {"options": {"bSimulate": False, "playMode": "PlayMode_InViewPort", "warmupSeconds": 8}})`, `capture_viewport(m, "x.png")`.
- Close the editor when done (`taskkill /F /PID <id> /T` on the process you started; give it 10 s to disappear from the process list). Never kill other compiler or CFD processes.

Playtest caveats (11 Oct 2026): about a third of runs lost all synthetic MOUSE input (many `no hit` / azimuth 0 results together) for a reason not yet found, and the run needs the UBT mutex free at start (do not build in another worktree while it runs). Rerun before believing a regression; see `docs/progress/2026-10-11-unreal-m1-playtest/INDEX.md`.
