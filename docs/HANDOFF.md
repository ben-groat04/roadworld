## 1. Product framing (the person, 11 Oct)

"This is a game, we will just be placing the road in the open world and I expect it to then with only that be what you'll be comparing to the images. So all the stuff has to come from the existing world and the road edge scatter."

Consequences (Round 35):
- **Nothing is hand-dressed in look-test levels.** Everything in a picture comes from (a) a `world_cover` layer (ground and vegetation; seeded default, replaceable by a future world generator; pattern measured from the aerial references) or (b) road-generated content: surface, markings, kerbs, earthworks, verge and edge scatter, lighting columns. Placing a road clears world cover in its corridor.

## 10. How to run agents on this project (learned 10-11 Oct)

- **Unreal is a single lane**: one agent at a time builds the plugin or runs the editor. Queue Unreal work, do not parallelise it. Prefer the live editor through the MCP over cold-start scripts.
- **Own worktree and branch per code agent** (at least its own build dir with CLEAN builds). The shared checkout caused stale-object false crashes, build breaks from other agents' half-edits and data/binary mismatches. Merge one agent at a time; run the full suite on both compilers after each merge.
- **Watch the usage limit.** 5-7 concurrent agents exhausted the limit at 02:40 on 11 Oct and killed two agents mid-edit. Run at most 3-4 at once, finish before starting more, resume an agent that has context rather than spawn a new one, stop agents that re-send finished reports, commit work-in-progress before the limit can cut it off.
- **Agents always run in the background**; one failed foreground launch blocks the whole turn. So do pushes, builds and CI watches.
- **Every push carries `[skip ci]`** until the person asks for a CI run (last CI-verified commit `1ae80b0`).
- **Research Unreal/plugin/tool facts with agents; never answer from memory.** Verify guesses against `C:\UE_5.8` source.
- **Reference claims**: any statement about what the photos show must come from images actually opened, with the files listed; review briefs set a minimum (at least three per view); the main session checks the count before acting on a review. A review based on 2 photos produced six wrong claims that reached builders (`docs/research/reference-claims-audit.md`).
- **Briefs**: never state a rule as an absolute ("as many tiers as needed") without a sanity bound (that produced the ziggurat); require the result to be looked at and judged before reporting; require agents to list what they did NOT verify. Render and cold-read every geometry or look change before building on it.
- **Check commits landed** (`git status -sb`), do not trust an exit code (a failed `git add` path once left work uncommitted).
- After an agent reports "N/N tests pass" in a shared tree, trust only a clean build of the merged state.
- **Send the person pictures as files** whenever new visual results exist; they often follow from a phone.
- Road-engineering details: the assistant decides with region-data defaults (and a toggle where practice varies). Product direction, scope, purchases, downloads and anything irreversible: the person decides.
- Other standing rules are in `CLAUDE.md` and Claude's memory: main session does not write code or audit screenshots; free/cheap first; not UK-only for region-neutral things.
