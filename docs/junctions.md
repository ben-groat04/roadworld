# City Painter: junction generator (interface v1)

10 Oct 2026. Interface: `sim_core/include/cp/junction.h`. Tests: `tests/test_junction_interface.cpp`. Decisions come from `planning-log.md` (Junctions) and `road-graph-model.md` (§3, §5).

## 1. Data flow
```
RoadGraph + RegionPack + JunctionOverrides
  -> collect_arms        arms CCW by heading_out: lanes, widths, kerb offsets, centreline   [junction.cpp, real]
  -> classify_arms       End | Joint | Junction | Merge | Diverge                                [real]
  -> major_arm_indices, resolve_corner_radii                                                     [real]
  Junction:          compute_trims (B) -> generate_connectors (A) -> generate_geometry (B)
  Merge / Diverge:   generate_merge_diverge (C) does trims, connectors and geometry for the node
  -> JunctionSet { NodeId -> Junction }   (nodes with 3+ arms only)
```
Lane graph first, geometry second: A reads only `arms`, `trims`, overrides (never B's polygons), and B never reads connectors. The one coupling is `trims`, via `compute_trims`. `build_junctions(..., only)` rebuilds just the dirty nodes. Everything is derived and never saved; the saved state is `JunctionOverrides`.

## 2. Frames and ordering (shared conventions)
- Each arm is in its own outward frame: s = 0 at the node, `heading_out` away from it, lateral + = left of `heading_out`. `arm_point(arm, s, lateral)` reads the arm's full edge centreline (0..edge_length); only normal-junction trims are capped at 40 m (`kArmSampleLength`), merge/diverge trims at edge_length / 2.
- Arms sort CCW by `heading_out`. Corner k is between arms[k] and arms[k+1], keyed `(node, edge_l = arms[k+1].edge, edge_r = arms[k].edge)`.
- `LaneRef` lists only connecting lanes (lane type `connects_at_junctions` with a travel direction), so pavements, parking and shoulders are excluded. `lane_from`/`lane_to` index `arm.lanes`; override keys use the stable `slot`.
- Polygons are `std::vector<std::vector<Vec2>>`: outer rings CCW, holes CW.

## 3. Trim contract (B -> A)
`compute_trims(arms, radii)` (real, in `junction_geometry.cpp`) returns, per arm, the distance from the node to the junction boundary. For corner angle theta (CCW arm k to arm k+1) and kerb offsets a = arms[k].kerb_left, b = arms[k+1].kerb_right, the kerb lines meet at `a*cot(theta) + b/sin(theta)` on arm k and `a/sin(theta) + b*cot(theta)` on arm k+1. The fillet tangent points lie `r/tan(theta/2)` beyond. An arm's trim is the max over its two corners (theta >= 180 deg gives no corner), clamped to [0, min(edge_length/2, 40 m)].
A's connector paths **start and end exactly on the trim lines**: first point `arm_point(from, trims[from], lane.lateral)`, last point `arm_point(to, trims[to], lane.lateral)`, tangent to the lanes there. B's carriageway polygon is bounded by the same lines, so lanes and asphalt meet without a gap. Edge meshes are cut at `trims[i]`.

## 4. Parts
**A, connectors** (`junction_connectors.cpp`): for every inbound lane x outbound lane on a different arm, one `LaneConnector`. No auto turn pockets, no U-turns by default (only an enabling override creates one). `kind` from `classify_turn` (real; thresholds 30/150 deg; left is Nearside under `DrivingSide::Left`, mirrored otherwise). `path` comes from `make_connector_path` (also used by C). `conflicts` = indices of connectors crossing in plan (|dz| < region `plan_crossing_junction_dz_m`) or ending in the same lane. Disabled connectors stay in the list with `enabled=false`, so the UI can re-enable them. Order is deterministic (arm_from, lane_from, arm_to, lane_to).
**B, geometry** (`junction_geometry.cpp`): fills `corners` (fillet kerb polylines, empty where the kerb runs straight), `carriageway`, `pavements`, `crossings` (one per arm, just outside the trim line, perpendicular, kerb to kerb). Use Clipper2 (`third_party/clipper2`, link target `clipper2`, already a dependency of sim_core) for union/offset: carriageway = union of arm stubs and corner wedges; pavements = offset of the carriageway minus the carriageway. Clipper2 builds with `-fno-exceptions`: it checks `__cpp_exceptions` and turns errors into no-ops, so an empty result must be treated as failure. It uses Int64 internally; use `PathsD` with precision 3.
**C, merge/diverge** (`junction_merge.cpp`): classification is already real (all three arms one-way, two same-direction arms within 45 deg, the third >= 135 deg from both). C owns the node: sets `trims` itself (the gore point; the corner formula blows up as theta -> 0), maps lanes across (lane add/drop, taper) into connectors via `make_connector_path`, and fills the same polygons. Lane counts need not match.

## 5. Overrides survive regeneration
`JunctionOverrides` holds `connectors[(node, from_edge, from_slot, to_edge, to_slot)] -> {enabled, via}`, `corner_radius[(node, edge_l, edge_r)]` and `lane_connects[(node, edge, slot)]`. All keys are stable IDs, so a rebuild looks them up and re-applies them. A custom curve stores only interior control points (`via`); the end points are re-snapped to the current trim lines, so changing a radius or a neighbour does not invalidate it. On an edge split the *commands* remap keys to the new edge touching the node (§5 of road-graph-model) and record any dropped ones for undo; the generator never mutates overrides. Unmatched keys are ignored.

## 6. Side-agnostic rules
Only `DrivingSide` decides nearside; nothing branches on left/right except `classify_turn`/`turn_is_left`. Lane `inbound` is derived from `Lane::dir`, which is already mirrored by `instantiate_lanes`. Tests run both sides and expect nearside/offside counts to be identical. Major arm: highest `road_class` (design speed in km/h, a proxy until the pack has an explicit class), then widest cross-section; ties keep all tied arms. Signals and priority are out of v0, but `major_arms` is the input for give-way markings.

## 7. Roundabouts (`junction_roundabout.cpp`)
**Model (decided Round 29).** A roundabout is not one merged junction. Its ring is ordinary, individually editable one-way edges, and every ring node keeps its own `Junction` (so the player can drag, split, retype or delete any part, and connector/corner overrides work per node exactly as anywhere else). "Roundabout" is a property layered on top, and it comes from an explicit road type, never from shape: a region-pack road type with `roundabout_ring: true` (UK: `roundabout_ring`, one-way, two 3.5 m driving lanes). A *group* is a closed directed loop made only of edges of such types, circulating the way `DrivingSide` dictates (clockwise for left-hand traffic). A one-way loop of ordinary types is never a roundabout. The place tool is only a preset that draws the ring.
- **Finding groups** (`find_roundabouts(graph, region, only = {})`): walks only flagged edges, as connected components. A clean ring has exactly one flagged in-edge and one flagged out-edge at every node, >= 3 nodes, every edge one-way and not a self-loop, and the right circulation. Anything else that is flagged (open chain from a mixed loop, figure of eight or two rings sharing a node, wrong direction, a two-way edge of a ring type) is returned in `RoundaboutScan::problems` and shown as `degraded` on the junctions of its nodes; it is never guessed into a group. With `only` (dirty nodes) only rings touching those nodes are walked.
- **A group exists as soon as the loop closes.** The island is built and the nodes are marked even with no approach roads; there is no minimum arm count. Splitter islands appear only on two-way approaches.
- **Post-pass** `apply_roundabouts(set, graph, region, overrides, only = {})`, now called at the end of `build_junctions` (use `build_plain_junctions` to skip it): for each group it rebuilds the ring nodes with forced kerb radii (approach / ring-out 8 m, ring-in / approach 12 m, island-side corner = ring radius; all from `RoundaboutRules`, a player corner override wins), sets `kind = Roundabout` and `group_nodes` on each ring node's junction, and gives ring nodes with only the two ring arms a Joint-class junction (trims 0, the lane continuations, no polygons) so `JunctionSet::find` works for every ring node. If the layout cannot be built (island under `min_island_radius`, empty offset) the error is on `RoundaboutLayout::error` and every ring junction is `degraded` with reason "roundabout: ...". No whole-ring connector chains: moving round the ring is just successive per-node connectors, and lane discipline comes from them. Full-circle U-turns are available by default (an approach-to-ring and a ring-to-approach connector exist at every node).
- **Group result** (`RoundaboutLayout`, one per group, not on any `Junction`): `island` (inner kerb offset of the ring, Clipper2), `splitters`, and `give_way`: for each approach-to-ring-out connector (an entry) the ring-in to ring-out connectors it yields to, keyed by (node, connector index). Priority data only; lane choice and other traffic policy are parked (planning-log section 5). Wanted later on `LaneConnector`: `bool give_way; std::vector<int> yields_to;`.
- **Tool** `make_place_roundabout(centre, radius, ring_type, region)` (one undo step; redo keeps ids; `check_place_roundabout` returns the reason it would fail): radius within the region's `min_tool_radius`..`max_tool_radius` (UK 8..100 m) and an island of at least `min_island_radius`. Roads crossing the circle are cut at it (the inside part and nodes left inside are removed, the normal split-on-crossing rule); refused, graph untouched, if a road lies wholly inside the circle, a roundabout ring or a bridge/tunnel crosses it, or a stub or ring edge would be under `min_edge_length`. Ring: >= 4 nodes, arcs <= `max_arc`, flat at the clicked height, tangent headings. Overrides keyed to a deleted node are not remapped.
- **Export:** JSON gains a top-level `roundabouts` array (nodes, edges, centre, radius, `ok`/`error`, arms, island, splitters, `giveWay`) and `roundaboutProblems`; `junctions[].islands` still carries the island and splitters on the group's first ring node for older viewers.
- **Tunables** live in `region.json` `roundabout` (`RoundaboutRules`, with fallbacks only when a pack omits them).

## Note: `degraded` and curved short arms
`Junction::degraded` means the geometry could not be made consistent (solver stall, kerb intersection beyond the trim line even at radius 0, empty carriageway union). A fillet merely clamped by the trims is not degraded: compare `CornerCurve::radius` with `requested_radius`. Ring nodes are the hard case for the general generator (two tightly curving ring arms plus an approach, trims clamped to half of short ring edges); `test_junction_roundabout` sweeps inscribed radii 11 to 100 m, 3 to 6 arms, 1- and 2-lane rings, both driving sides, and requires non-degraded, non-empty, simple polygons and a kerb at every real corner.

## 7b. Approach shaping, size classes, class-pair radii (Round 30)
- **Flare** (`ArmFlare`, `flare_spread`, `flared_lateral` in junction.h): derived, never authored. On a shaped arm both kerbs and the lanes inside them lie `spread` metres further out, constant up to `full` (the fillets sit inside it), smoothstep to 0 at `length` = the arm's trim. Lanes therefore keep their full road-type width beside a splitter island; total carriageway width grows monotonically toward the ring. Requested through `JunctionOverrides::arm_shapes` (`ArmShape`), filled by `build_roundabout`; the far end of the edge may be used up to 2 m from it when it is not a junction, else half the edge. A shape that does not fit is dropped and the junction is `degraded` ("splitter island on edge N does not fit"). Consumers: edge meshes already stop at `trims`; junction carriageway/pavement polygons, connector paths (they follow the shifted lanes) and splitter polygons carry the widened approach; markings should place lane lines and give-way lines with `flared_lateral`.
- **Size classes** (`region.json roundabout.size_classes`, by ring radius): entry/exit kerb radii (tight entry, generous exit), splitter length (times a speed factor of the approach) and width, over-run apron (`RoundaboutLayout::apron`, island shrinks inside it when the island radius is under `apron_island_radius_max_m`). Dual-carriageway approaches get a splitter that is the central reservation carried into the ring (`SplitterIsland::arm_b`).
- **Class-pair corner radii** (`region.json junction.corner_radius_by_class`, `skew_factor`): the default radius depends on the pair of road classes; scaled by corner angle / 90 degrees clamped to [0.6, 1.5] so the obtuse corner is larger. Player overrides win.
- **Turn pockets (PARTIAL, off in the UK pack: `junction.turn_pockets.enabled = false`)**: the generator (`plan_pockets`, pocket `ArmShape`, `TurnPocket`, offside connector via the pocket, `JunctionOverrides::turn_pockets`) is written but untested and not wired to a command. Design: the offside kerb and outbound lane of the major arm shift out by the pocket lane width (flare), the freed strip is the pocket lane (`TurnPocket::lane`) for `storage_length`, then a hatched ghost island (`ghost`, paint only) on the 1:N taper; only the offside-turn connector (`via_pocket`) uses it. Render: junction polygons already carry it; markings: hatch `ghost`, lane lines/arrow on `lane`; grading: wider formation inside the trim. Still to do: tests, override command, enable.
