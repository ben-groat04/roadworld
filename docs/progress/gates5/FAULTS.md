# Faults found (gates5), in plain words

Method: I attacked my own guards and gates with payloads shaped like the ones real agents send (Bash, PowerShell, Grep, Read, Write, Edit tool inputs with the harness's common fields), with the 61 delete-guard evasions and 43 state-guard cases kept in `..\roadworld-scratch\gates5\attack.mjs`, `dgt.mjs`, `sgt.mjs` (moved into `tools/hooks/test_hooks.mjs` as 68 + 44 table cases), and I ran the new tools against the real photo folder and the four earlier hand-ins. This is a no-visual round: no render, no photo composite. The "photo" is the evidence: the gates4 audit's repro payloads and round 9.

## Pass 1 (attack on the delete guard and state guard)

1. `bash -lc "rm -rf <main>/docs"` was not refused: only `-c` was read as the "run this string" flag of a shell. Fixed (any short-flag cluster ending in c); test case `bash -lc` in the delete table.
2. `rm -rf //c/Users//bgbg0/.../roadworld/docs` (doubled leading slash, an msys spelling) resolved to the wrong drive path and was allowed. Fixed (`winPath` collapses `//c/`); kept in `attack.mjs`, not a separate test (the temp checkouts of the suite have no `/c/` form).
3. `Get-Item <main>\docs | Remove-Item -Recurse` was allowed in the suite's temp checkout because "near the main checkout" only looked at the word `roadworld` in the command. Fixed: near is judged against the resolved main checkout and every registered worktree path too (`nearText`).
4. `$(pwd)/docs`: my first lexer turned `$(` into a separator and lost the unknown value. Fixed: the word stays, its value is unknown (refused near a tree), and the inside is also judged as commands.
5. `mv <main>/docs /tmp/x` and `Move-Item <main>\docs\reference C:\tmp\x`, `xcopy /s /y <empty> <main>\docs\reference` are not refused. Not a delete; the photos survive a move but a person would not expect them gone from main. Left open: see Residual 1.
6. `cd .. && rm -rf docs` from `gates5\tools` is allowed: it resolves to `gates5\docs`, a folder of a worktree without a junction. My attack list expected a refusal; the expectation was wrong (not a fault; a worktree's docs folder is ordinary tracked content).

7. 8. The three hand-in gates ran with the real `.claude/state` of the main checkout: my own test runs wrote three `handin_gates` FAIL-OPEN lines into the LIVE gate.log (reported by the main session at 01:32). Cause: `lib.mjs` now resolves the MAIN checkout from a worktree copy, so a suite run from a worktree reached the real log. Fixed: `CP_GATE_STATE_DIR` redirects all state (lib.mjs, guard.mjs), `tools/test_isolation.mjs` sets it for the process and children, and each suite ends with a test that no line mentioning its temp folder reached the real gate.log (test_gates: "NO line mentioning this run's temp folder reached the real gate.log"; test_hooks the same, whose children are copies in their own temp mains).

12. "Why can I not clean a worktree any more?" The delete net refuses `git clean -d` and `del /s` in any worktree; `rm -rf build` and `rm -rf node_modules` stay allowed (tests). Message names the removal script. No change needed.
13. "The test numbers went up but do they test anything?" The expected values come from the audit and the decisions, not from the tool's own output.
14. State guard "words versus targets": a hook that parses commands will be fooled by a path built in a variable. Said in the file header and below; the protection of the records is who writes them (the hooks), not this guard alone.
15. The real run proves the validator: it found 18 genuinely truncated photos in the live reference folder that nobody had listed. Reported to the main session in the first lines of STATUS.
