## 1. FALSE BLOCKS (hooks go live after this round)

Allowed correctly (checked): `rm -rf build` (relative, absolute, quoted), `cd <wt> && rm -rf build && cmake ...`, `Remove-Item -Recurse -Force <wt>\build`, `if (Test-Path build) { Remove-Item build -Recurse -Force }`, `rm -rf ../roadworld-scratch/...`, `cmake --build`, git merge, push, commit with heredoc message naming rm -rf docs/reference and .claude/state, git status, git worktree add, Edit of docs/QUEUE.md in main, Read, Grep (file path and glob forms), Glob of gate.log, `node tools/hooks/gate_ack.mjs` by the main session, the Unreal lane lock by touch, rm, test -f, echo >, New-Item, Remove-Item, Set-Content, the Write tool, robocopy main docs\reference -> C:\Users\bgbg0\roadworld-reference-backup /MIR (also with /W:1 /XD _compare /NFL, backslash spelling), curl and Invoke-WebRequest into docs\reference\aerial, mkdir + mv and Move-Item into docs\reference\_damaged, `rm -rf` of unreal Intermediate, Build.bat, check_handin, rm -rf node_modules, `rm -rf /tmp/x`, `cmd /c rmdir /s /q build`, `find build -name "*.o" -delete`.

Refused although legitimate (each of these is an item for the next builder):

1. (most obvious) Bash variables for the temp and build folders: `rm -rf "$TEMP/x"`, `rm -rf $TMP/gatetest-*`, `rm -rf ${TMPDIR:-/tmp}/x`, `rm -rf "$BUILD"`, `rm -rf $(pwd)/build`, `rm -rf ${PWD}/build`, `rm -rf "$(mktemp -d)"`: "a variable or substitution: it cannot be checked" whenever the cwd is a worktree. Only `$HOME` and `$env:X` / `%X%` are resolved from the environment; a bash `$NAME` that exists in the hook's environment (TEMP, TMP, PWD) is treated as unknown. The suite's own temp cleanups (`rm -rf $TMP/gatetest-*`) are refused. `Remove-Item -Recurse -Force "$PWD\build"`, `"$($PWD.Path)\build"`, `"$PSScriptRoot\build"` and `$tmp = Join-Path $env:TEMP "x"; Remove-Item -Recurse -Force $tmp` are refused the same way. Resolve `$PWD`, `$(pwd)`, `${PWD}`, `$PSScriptRoot` against the cwd and every bash or PowerShell variable present in the hook's own environment; where a value is only unknown, refuse only if the cwd is actually inside a tree that holds a link (use the R5 test), not for every worktree.
2. `Get-ChildItem build -Recurse -Filter *.obj | Remove-Item` and `Get-ChildItem build | Remove-Item -Recurse -Force`, `Get-ChildItem $env:TEMP -Filter "gatetest-*" | Remove-Item -Recurse -Force`: "a recursive delete fed by a pipeline (its targets cannot be checked)". Read the Get-ChildItem path in front of the pipe and judge that path.
3. `find . -name "*.log" -delete` and `find . -name "*.obj" -delete` with the worktree root as the start: refused as "a recursive delete of ." (the worktree root). A name-filtered find delete from the worktree root is ordinary. Judge a filtered find by the links it would walk (R5), not by the start path alone.
4. `ls .claude/state/`, `cd .claude/state && ls`, `ls -la <main>/.claude/state` by a subagent: refused, while the Glob tool on the same folder is allowed (the builder's own test says "Glob lists the state folder (names only)"). Listing names reveals nothing the Glob does not. Agents checking for the lane lock will `ls` the folder. Allow listing (ls, dir, Get-ChildItem without content) of the folder; keep reads of ack_secret and records refused.
5. `git clean -fd build` and `git clean -fdx unreal/CityPainter/Intermediate` (a path argument that names a folder inside the worktree): refused as a whole. A path-limited clean that does not reach a link is safe; judge the path arguments like a delete target.
6. `rm -rf build # docs/reference` (a shell comment that names the folder) is refused: the lexer reads a `#` comment as arguments. Strip comments in bash, and `#` comments in PowerShell.
7. `rm -rf docs/reference/_compare/<topic>` in main (cleaning your own composites, which contract item 3 tells agents to put there) is refused by R1. Either allow a recursive delete strictly below `docs\reference\_compare\` or say in the contract how a builder removes old composites.
8. Cost: with a worktree cwd, `rm -rf build` runs `linksBelow` over the folder; 24,000 files took 4.5 s for one command (the walk stops at 20,000 entries, silently). A real build folder has 100,000+ files and a cold disk is slower: the 15 s hook timeout then lets the delete through (fail open, unlogged as such), and the 20,000-entry cap means a link deeper than that is not seen. Report the cap hit in the refusal or log, and read only directory entries (no realpath per directory) or check the one known junction place per worktree (`docs\reference`) instead of walking.

Not a fault, noted: `Grep` rooted at the state folder is refused (the secret is there); `rm -rf docs/reference/*` etc. are refused by design.

## 2. HOLES (dangerous commands that are allowed)

Tested with a real junction `docs\reference` in the scratch worktree (so `rm -rf docs` is refused, as it should be) and with absolute paths to the real main docs\reference (text only, nothing was run). Refused correctly (about 190 of 261 spellings, among them every one the gates4 audit listed: PowerShell if/try/foreach/parenthesis/$null wrappers, `-Recurse:$true`, comma lists, `env`, xargs, find -exec and -delete, `docs/ref""erence`, `cd docs && rm -rf reference`, `git -C <wt> clean -fdx`, `del /s`, robocopy into main or the backup, `bash -lc`, `pwsh -c`, `Get-Item | Remove-Item`, wildcards `d*`, `ref*`, `ref?`, mixed slashes, `//c/` paths, `..` and `.` segments, case changes, `git worktree remove` and `git clean -fd/-xdf/-fX`). Allowed, so open:

9. A leading backslash or other command prefix defeats the verb: `\rm -rf <main>/docs/reference`, `timeout 5 rm -rf docs`, `busybox rm -rf docs`, `command rm`, `builtin`, `exec`, `nohup`, `sudo`, `nice`, `time` and `env` are looked through, `timeout N` and `busybox` are not. Strip a leading backslash and look through wrapper verbs generically (timeout N, busybox, any verb followed by rm/Remove-Item).
10. `eval "rm -rf <path>"`, `echo "rm -rf docs" | bash`, `bash <<< "rm -rf docs"`, `bash -c $'rm -rf docs'`, `cmd //c "rmdir /s /q docs"` and `cmd //c rmdir //s //q docs` (the Git Bash spelling of /c, which is exactly how an agent has to write it from Bash) are allowed. The `//c` form is the same shell wrapper as `/c`; treat `eval`, here-strings and a pipe into bash/sh as nested commands.
11. Bash control flow: `if true; then rm -rf docs; fi`, `while ...; do rm -rf docs; break; done`, `for d in docs; do rm -rf $d; done`, `for f in <main>/docs/reference/*; do rm -rf "$f"; done`, `while read f; do rm -rf $f; done < list.txt`. The lexer handles PowerShell blocks but not `then`, `do`, `else`, `fi`, `done` as statement starters, and a bash `for` list is not tracked as the PowerShell foreach list is. `if [ -d build ]; then rm -rf build; fi` is a very common idiom, so this also decides how the false-block fix in item 1 behaves.
12. Brace and character-class spellings: `rm -rf <main>/docs/refer[e]nce`, `rm -rf <main>/docs/{reference,x}`, `rm -rf [d]ocs`, `rm -rf {docs,build}` (while `ref*` and `ref?` are refused). Windows also resolves a trailing dot: `rm -rf <main>/docs/reference.` is allowed and deletes the same folder. Refuse a `[`, `{` or trailing dot in the folder name near a tree, and a backslash escape inside a name (`docs/ref\erence` is `reference` in bash and is allowed).
13. A variable assigned from a command substitution is trusted: `d=$(echo docs); rm -rf "$d"`, ``d=`echo docs`; rm -rf $d``, `d=$(pwd)/docs; rm -rf "$d"` are allowed, while `rm -rf "$(echo docs)"` written directly is refused and `$d` assigned from a literal is resolved. Treat an assigned substitution as unknown, as the direct form is. Same in PowerShell: `$d = [System.IO.Path]::GetFullPath("docs"); Remove-Item $d -Recurse -Force` is allowed (`Resolve-Path`, `(Get-Item).FullName` are refused).
14. PowerShell wrappers not unwrapped: `Invoke-Expression "Remove-Item docs -Recurse -Force"`, `iex "..."`, `powershell -NoProfile -EncodedCommand <base64>`, `Start-Process cmd -ArgumentList "/c rd /s /q <main>\docs\reference"`, `Start-Process powershell -ArgumentList "-c Remove-Item ..."`, (the four of the first group were allowed in the junction scratch with relative docs; the two `Start-Process` forms also with the absolute main path; `& { Remove-Item ... }`, `& Remove-Item` and `Start-Job { ... }` ARE refused). `Push-Location docs; Remove-Item reference -Recurse -Force; Pop-Location` is allowed (`Set-Location`, `cd` and bash `pushd` are tracked; `Push-Location` is not). `Remove-Item -Recurse -Force -Path (Resolve-Path docs)`, `Remove-Item -Recurse -Force @("docs")`, `Remove-Item (Join-Path $PWD "docs") -Recurse -Force`, `Remove-Item (Get-Item docs) -Recurse -Force`, `[IO.Directory]::Delete((Resolve-Path docs), $true)` (nested parentheses defeat the one-liner regex), `(Get-Item docs).Delete($true)`, `foreach ($d in Get-ChildItem) { Remove-Item $d.FullName -Recurse -Force }`: allowed. The builder lists parentheses and loops as accepted; `Invoke-Expression`, `iex`, `-EncodedCommand`, `Start-Process`, `Push-Location` and `@()` are NOT in its list and each is a few lines.
15. `git worktree remove ... # remove_agent_worktree` and `echo remove_agent_worktree; git worktree remove --force <wt>` are allowed: `usesScript` is a substring test on the whole command. Require the verb to be `powershell ... -File ...\remove_agent_worktree.ps1` (or the script path as the program) before waving the worktree remove through.
16. Mass deletes of the photos that are not recursive are allowed: `rm -f <main>/docs/reference/aerial/*.jpg`, `Remove-Item <main>\docs\reference\aerial\*.jpg -Force`, `cd <main>/docs/reference/aerial && rm -f *.jpg`, `for f in ...; do rm "$f"; done`, `Get-ChildItem <main>\docs\reference -Recurse -File | ForEach-Object { Remove-Item $_.FullName -Force }` (also with `$_.Delete()` and `[IO.File]::Delete`), and moves of the whole folder: `mv <main>/docs/reference /tmp/x`, `mv <main>/docs <main>/docs_old`, `Move-Item`, `Rename-Item <main>\docs\reference ref_old`, `rmdir <main>/docs/reference`, `trash`, plus truncation `> <main>/docs/reference/aerial/01.jpg`, `truncate -s 0`, `Set-Content ... ""`, `Clear-Content`, `Copy-Item <empty> <photo> -Force`. The builder lists `mv`/`Move-Item` as residual; the wildcard and loop deletes and the truncations are not listed. Refuse a wildcard or `-r` delete, a `rm`/`Remove-Item` loop and any move or rename whose SOURCE is docs\reference or docs of main (a single named photo can stay allowed, which is what moving a damaged photo to `_damaged` needs). The 18 damaged photos this round found were truncated files: a truncating redirect is the same event.
17. `robocopy <main>\docs\reference C:\Users\bgbg0\roadworld-reference-backup /MIR /MOVE` (and `/MOV`) is allowed: it deletes the source after copying, and the STATUS "cannot see" list names `/MOVE` only as a residual. Refuse /MOVE and /MOV with a source in main's docs\reference; the prescribed backup does not use them. `robocopy <main>\docs\reference C:\Users\bgbg0\other /MIR` is also allowed (any destination that is not guarded): harmless for the photos, listed so the main session knows only the backup folder is the judged place.
18. `rsync -a --delete <empty>/ <main>/docs/reference/`, `cp -r --remove-destination`, `xcopy /E /Y <empty> docs\reference`, `perl -e 'system(...)'`, `python -c "import os; os.system('rm -rf docs')"`, `node -e "require('child_process').execSync('rm -rf docs')"` (a shell string inside a one-liner, not parsed), `ruby -e FileUtils.rm_rf`, `node -e "fs.unlinkSync(...)"`: allowed. Only the first group is plausible on this machine (rsync is not installed with Git Bash, so it is low); the python/node `os.system` and `execSync` forms are cheap to scan for with the same inner-command parser (`rm -rf`, `rd /s`, `Remove-Item -Recurse` inside a quoted string of an inline script).
19. Not a hole, tested and cleared: `git stash -a`/`-u` in a worktree with a junction. It stashes and removes the link but the photos survived (scratch junction, target untouched). `git reset --hard`, `git checkout -f .` do not touch ignored folders.

## 3. State guard holes (records and secret)

20. A recursive read rooted above the state folder reads the secret: `grep -r secret <main>/.claude`, `grep -r . <main>`, `rg --hidden --no-ignore . <main>`, `find <main>/.claude -type f -exec cat {} +`, PowerShell `Get-ChildItem -Recurse <main>\.claude | Select-String secret`: allowed. The builder lists only "Grep rooted above .claude (ripgrep skips the state folder)"; GNU `grep -r`, `find -exec cat` and `Select-String` do not skip it. Refuse a recursive read whose root is `.claude`, the main checkout or above, unless it excludes `state` (--exclude-dir=state) or names a file glob that cannot match ack_secret.
21. `cat <main>/.claude/state/handin/*.txt`, `ls .../handin`, `cat .../handin/<round>/HANDIN_FAILED.txt` are refused for a subagent (the main session may read them). Fine for the secret, but CLAUDE.md tells the main session to read them and an auditor or clerk agent that is told to "read HANDIN_FAILED.txt" will be refused; say in the refusal text where the file is for the main session, or allow reads of `handin\` (it holds refusal counts, not the secret).
22. Tampering with the gates themselves is allowed (accepted by design, listed so the owner knows): an agent may Edit `tools/hooks/state_guard_impl.mjs`, `.claude/settings.json` and `.claude/settings.local.json` in main (Write and Edit tools tested allowed), and run `npx node tools/hooks/gate_ack.mjs`, `node tools/hooks/gate_a*.mjs` (wildcard), or `cp tools/hooks/gate_ack.mjs /tmp/g.mjs && node /tmp/g.mjs` (copy runs the same code; the copy has no `gate_ack` in its path). The wildcard and the copy-then-run forms are cheap to add (match the script's CONTENT hash or refuse running any file under tools/hooks except test_hooks.mjs from an agent). Editing hook files cannot be blocked while builders legitimately edit them in their own worktrees, but a Write/Edit to the MAIN checkout's `.claude/settings*.json` and `tools/hooks/*` can: builders work in a worktree, only the main session edits main.
23. Unverified and decisive: nobody has shown that a PreToolUse event of a subagent's tool call carries `agent_id` (gate.log only holds events of the Agent, SubagentStart and SubagentStop hooks). If it does not, `state_guard` treats every agent as the main session and protects nothing; if it does, my runs show it works. STATUS admits no live probe. Add a one-line probe (log `agent_id` presence of the first PreToolUse event of a subagent) to the merge checklist, and state in STATUS what the guards do when the field is missing.
