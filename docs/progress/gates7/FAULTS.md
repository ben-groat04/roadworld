# Faults found (gates7), in plain words

Method: after fixing the 14 items of `docs/progress/gates6/AUDIT.md` and adding the git guard (item 15) I attacked my own changes with payloads shaped like the ones real agents send (Bash and PowerShell tool inputs with the harness's common fields, backslash cwds, a real junction fixture), then ran the changed tools on real data (the real photo folder, the real main root), then asked what a builder or the owner would say. No pictures exist (no-visual round). Every fault below has a named case in `tools/hooks/test_guards7.mjs` ("own fault list, pass 1": F1 to F3) or a run quoted here.

## Pass 1 (attack on my own fixes)

1. F1: `{rm,-rf,docs}` as the whole command line: bash brace-expands it into `rm -rf docs` and runs it; my lexer kept it as one word `{rm,-rf,docs}`, so no verb was seen. Fixed in `shell_lex.mjs`: a whole-word brace list as the FIRST word of a command is split into its words. Test "F1 a brace list as the whole command line" (refused in main, allowed on `build` in a clean worktree, `echo {a,b}` stays text).
2. F2: `find <main>/docs -type f | xargs rm` and `find <main> -name "*.jpg" | xargs rm` were allowed: my first item-7 rule only looked at a listing INSIDE docs\reference, but the photos live below main\docs and below main. Fixed: a listing rooted at main, main\docs or any folder above docs\reference, fed to rm / del / truncate / shred, is a mass delete unless the find's `-name` filter cannot match a picture (`find <main> -name "*.log" | xargs rm` stays allowed; `find . -type f | xargs rm` is refused in main and allowed in a clean worktree). Tests "F2 ...".
3. F3: `shutil.rmtree('bu' + 'ild')` (and any literal followed by `+`, `.join`, `%`) would have been read as the literal `bu`. Fixed: only a literal that is the WHOLE first argument counts; anything else stays unresolved and keeps the old refusal near a tree. `rmtree('build'); rmtree('docs')` judges both literals. Tests "F3".
4. The first version of the git guard read the agent's transcript (the whole JSONL) on every git command of every subagent. Fixed: G1 needs no transcript; G2 reads it only when the command WOULD be refused for a builder (a probe with a made-up HANDIN_DIR outside main), so ordinary git calls cost nothing.
5. `--git-dir=<main>/.git/worktrees/<n>` (a worktree's own git folder, lies under main) was read as "the main checkout". Fixed: the worktree git folders are excluded.
6. The wildcard fix for `state/*.log` first returned "allowed" for the wildcard and then fell into the old "gate records" refusal at the bottom of `judgePath` (the test caught it: `grep deny state/*.log` still refused). Fixed with an explicit return; test "item 4 grep deny state/*.log".
7. Inline node/python code that named `gate.log` was refused TWICE: once by the inline rule, once because the whole code string was also judged as a path argument. Fixed: the code argument is judged only as code. Tests "item 4 node -e reads gate.log", "python -c reads gate.log".
8. `Select-String -Path <state>\*` passed because `-Path` matched the `-pat...` pattern-flag rule I wrote first (the value was skipped as a pattern). Fixed with an exact `-Pattern` match; the test caught it before the first commit.
9. `cleanupTmp` refused to delete the test folder because the suite had pointed TEMP at its own sub-folder and `os.tmpdir()` moved with it. Fixed: the OS temp folder is read once at import. A leftover `guards7-*` folder shows it was the first run only.

## Pass 3 (what a builder or the owner would say)

14. "Will `git commit -a` by a merger in main be refused?" Yes (G1), by design: the brief says a merger or docs clerk commits with explicit paths (`git commit -m "..." docs/QUEUE.md`), which stays allowed. A merge itself (`git merge x`) in main by a NO-CONTRACT merger stays allowed (G2 needs a HANDIN_DIR outside main).
15. "Why is `parallel rm -rf ::: build` still allowed?" Because `build` in a clean worktree is allowed for every spelling; only a delete that would reach the photos or a link tree is refused. Tests "item 10 ... on build".
16. "Will the wrapper look-through block my `cmake -E rm`, `curl -d "rm x"`, `npm run x -- rm`?" `cmake`, `curl`, `npm`, `git`, `echo`, `grep` and about 80 other text and tool verbs are skipped; the quoted-string look-through applies to sixteen named wrappers only (script, watch, parallel, su, runuser, ssh, sg, flock, unbuffer, wsl ...). Tests "item 10 curl body is text", "cmake --build build -- -j4", "npm run build -- --watch".
17. "Why is `Get-ChildItem . | Remove-Item -Recurse` refused in a clean worktree and `-Filter build*` allowed?" The unfiltered listing deletes the whole root (a worktree root is never deleted); the filtered one is judged by the links it would walk, like `find -name`. Tests "item 3".
18. "Does the new test folder cleanup ever follow a junction?" No: `cleanupTmp` walks without following links, unlinks every junction/symlink first (`rmdir` of the link only), refuses anything that is not a direct child of the OS temp folder, then removes the rest; the fixture photos behind the junction are checked to survive in the same run.

## Residual

1. (accepted: the same main session decision of 23 Oct 2026 as before, "structural protection + validated backup") The guards stay a best-effort NET: script files, paths built from several steps, command-substitution results, aliases, and the other forms listed in the file headers are not seen.
2. The git guard cannot see a directory or path held in a variable or substitution (`git -C $wt add -A` is left alone: unknown is not main), a git alias, a commit made by a program, or a tool other than Bash and PowerShell. When the agent's transcript cannot be read G2 does not apply (G1 still does).
3. G2's WRITE list is the commands of the incident (add, commit, merge, reset, rebase, cherry-pick, push) plus pull, revert, am, stash, rm, mv, restore, checkout, switch. `git tag`, `git branch -D`, `git config` and `git update-ref` in main by a builder are not refused.
4. The wrapper look-through reads a delete or move verb as one of the unquoted words of an unknown verb's segment: `watch echo rm -rf docs` (a harmless echo run by watch) is refused as a false positive in main or near a tree; the message shows the judged command. Not worth a table of exceptions.
5. The backup validator still cannot catch a single flipped byte in a scan (a decoder without a checksum has no way; the manifest sha1 catches it after the first mirror), zero runs of 1 to 31 bytes that still decode, or damage inside progressive and arithmetic-coded JPEGs beyond structure and the 32-byte zero run. verify-only trusts size plus modification time against the manifest; `--full` re-hashes everything.
6. The `.[a-z]*` item: in a tree whose ONLY link is `docs\reference` the payload is correctly allowed (it matches dotted names only and never reaches `docs`); it is refused when a dotted folder holds a link (case "item 8 rm -rf .[a-z]* where a dotted folder holds a link"). Reason (b) for the plain-tree half: the audit's reading was doubtful, shown by that pair of cases.

Residual only unfixable: item 1, item 2 and item 3 are the main session's accepted limits of a text-reading net and cannot be fixed without running the command; item 4 is a deliberate trade (a wrapper hiding a delete cannot be told from one running echo without a table of every wrapper); item 5 is what a decoder without checksums cannot know; item 6 is not a fault (shown by both cases).
