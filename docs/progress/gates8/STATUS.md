## Locked tests and checkpoint hand-back, as built

LOCKED TESTS (`tools/hooks/lock_guard.mjs`, PreToolUse on Write, Edit, NotebookEdit, Bash, PowerShell). Locked = any file under a folder `tests/locked/` (any repository or worktree) and any file listed (one path per line, `#` comments, relative to the worktree root or absolute) in `LOCKED_TESTS.txt` in the hand-in folder of the prior round (the folder of the brief's `PRIOR-AUDIT:` file). Limited = a BUILDER subagent: an agent whose launch carried a HANDIN_DIR and no `AUDIT-OF:` line (read from its own transcript or the BRIEF-FILE it names). Auditors (NO-CONTRACT launches), clerks, agents whose launch cannot be read, and the main session (no agent_id) may write locked tests: that is how they get there. Refused for a builder: Write / Edit / NotebookEdit of a locked path; in the shell, redirects, rm / del / Remove-Item / unlink, mv / Move-Item / ren / Rename-Item (source and destination), cp / Copy-Item / robocopy / xcopy / rsync / ln onto it, tee, touch, truncate, Set-Content / Add-Content / Clear-Content / Out-File, `sed -i` / `perl -i`, `git rm`, `git mv`, `git checkout -- <file>`, `git restore <file>`, `git clean <path>`, `find <locked> -delete / -exec rm`, a listing of the folder piped into Remove-Item, `rm -rf tests` (a folder holding locked files), inline python / node / .NET code that names a locked path next to a write, delete or rename call. Message: "locked test: written by the auditor; make it pass, or write BLOCKED" plus the reasons. FAIL OPEN (logged) on any internal error. Auditor side: to lock a test the auditor puts it under `tests/locked/` in the audited worktree, or lists it in `LOCKED_TESTS.txt` beside AUDIT.md; the next brief carries `PRIOR-AUDIT: <path to AUDIT.md>`.

CHECKPOINT HAND-BACK. A builder may stop early with `<HANDIN_DIR>/CHECKPOINT.md`, first line `CHECKPOINT: <what is done> | images: <path>[, <path>...]`, naming at least one existing image (absolute, or relative to the hand-in folder or the worktree), written after the agent started. `node tools/check_handin.mjs <folder> --checkpoint` validates it. The finish hook (SubagentHandback and SubagentStop) lets it through once per agent, logs `gate=handin decision=checkpoint`, writes `.claude/state/handin/<agent_id>.checkpoint.json`, and counts nothing: no builder record, no refusal counter, no audit owed. The second hook call of the same finish (within 120 s, same file) is allowed too. Any later stop of that agent, or an invalid or stale CHECKPOINT.md, gets the full hand-in check, and the refusal message says why the checkpoint did not count. The final hand-in is checked in full.
