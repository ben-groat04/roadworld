## Live test of the case the builder skipped (background subagent report -> notice)
Throwaway repo under my scratchpad, nothing installed, bundled CLI 2.1.295, `-p --model haiku --permission-mode bypassPermissions`. Settings: one UserPromptSubmit command hook (exec form, `${CLAUDE_PROJECT_DIR}`) that logs its stdin and returns additionalContext "the secret code is PINEAPPLE-77". Prompt: launch one general-purpose agent with run_in_background true, end the turn, then report on the code.
Result: the hook ran TWICE. Run 1 for my prompt. Run 2 at 17:34:45, 8 s later, with `prompt` = "<task-notification><task-id>...", i.e. fired by the background agent reporting back. The model's final answer quoted "PINEAPPLE-77" from a system reminder labelled "UserPromptSubmit hook additional context". Stdin fields seen: session_id, transcript_path, cwd, scratchpad_dir, prompt_id, permission_mode, hook_event_name, prompt. So the docs claim holds and the builder's stated reason for not testing ("headless runs end before background agents return") is FALSE: `-p` waited for the agent.
Docs passages checked: "A background subagent reporting back to the session that started it" (UserPromptSubmit fires); "Plain stdout and the additionalContext value are each injected as a system reminder that starts with the hook's name"; PreToolUse "A hook that blocks by exiting 2 routes the same way as deny"; SubagentStop "Returning decision: block with a reason keeps the subagent running"; SubagentStart "can't block subagent creation, but can inject context" (and I received the injected contract in this very run: my transcript has a hook_additional_context attachment after the prompt, so contract_inject works live). Docs also say a PreToolUse command hook that times out "doesn't block the tool call", so a hung brief gate fails open (unlogged).

## Faults, ranked by how easily a rule is skipped without anyone knowing

1. A stale, already-passing hand-in folder lets an agent stop at once (existing hook, not new). check_handin and handin_gate never check that the folder was written during this agent's run, and brief_gate accepts any absolute HANDIN_DIR.
   Repro: sandbox with a passing folder `old round/docs/progress/old` (3 files in docs/reference, valid STATUS/FAULTS/COMPARE); transcript whose first user line has `AGENT-CONTRACT-MARKER: v1`, `HANDIN_DIR: <that folder>`, an Owner's words quote. `node tools/check_handin.mjs <folder> --main <root>` exits 0; feeding handin_gate a SubagentStop event for that transcript exits 0 with empty stdout and logs "allow". A careless brief (or lazy agent) gets no hand-in work enforced and no notice. Fix idea: require STATUS.md mtime after the agent's first transcript timestamp, and HANDIN_DIR inside the agent's own worktree.
2. Nothing protects the log that every notice depends on. Delete `.claude/state/gate.log` (or append any `{"gate":"ack",...}` line, or run `gate_ack.mjs "aaaaaaaaaaaaaaaaaaaa"` from the main checkout, which any agent started there can do): all pending FAIL-OPEN, released hand-ins and NO-CONTRACT items vanish, and with the log gone the canary sees no entries and reports nothing. Repro: log with one FAIL-OPEN line -> gate_notice prints the notice; `rm gate.log` -> gate_notice prints nothing, exit 0. The ack clears everything at once, not per item, and checks only length (20 junk characters accepted, 19 refused, 30 spaces refused).
3. The launch gate covers only the Agent tool. Other spawn paths in this harness (the Workflow tool, which the docs list among matchable tools; start_session; SendMessage resumes) are not matched in settings.json, and the exempt types (Explore, Plan, claude-code-guide, statusline-setup) skip everything although Explore has Bash. Not tested live; read from settings.json and EXEMPT_TYPES. Unverified whether those paths fire SubagentStart (contract_inject would still run if so).
4. No canary for the hand-in gate. RULE 1 watches brief/inject lines only; RULE 2 only gate_notice. If SubagentStop/SubagentHandback wiring dies, nothing says so. Live evidence this class already happens: the real gate.log holds `{"gate":"handin","event":"SubagentStop","agent_type":"","reason":"FAIL-OPEN: no readable agent transcript"}` (17:26:04), a hand-in gate that did not run for one agent. The notice will now show it once, but a fully dead gate would still be silent.
5. Block counter is per agent_id and never reset. handin_gate writes `.claude/state/handin/<id>.json` on a block and never deletes it on a pass. A resumed agent (same agent_id, SendMessage) that failed twice earlier and is blocked once more is released at once with HANDIN_FAILED. The PreToolUse and SubagentStop paths also share the counter. Read from code; not reproduced.
6. A NO-CONTRACT line with a junk reason passes. Repro: prompt `do x` + newline + `NO-CONTRACT: aaaaaaaaaaaaaaaaaaaa` -> exit 0. It now surfaces as a notice until acked (the mitigation), but that agent gets no hand-in gate. A fake contract also passes: marker line + `HANDIN_DIR: C:\Users\a b\x y\docs\progress\r` + `## Owner's words` with any quoted text -> exit 0. A regex cannot fix this; the verbatim-quote check stays with the main session.
7. gate_notice with empty or non-JSON stdin logs FAIL-OPEN and prints NO pending notice even when items are pending (repro: log with a FAIL-OPEN line, then give the hook empty stdin -> empty output). Claude Code always sends JSON (seen live), so low.
8. Log parsing: a UTF-8 BOM on line 1 (e.g. after a PowerShell edit) drops that line silently, and a truncated last line is skipped silently. Repro: BOM line + a cut-off JSON line -> notice empty. Low.
9. gate_ack race: through_line comes from a second read after pendingItems, so an item logged between the two reads is acknowledged unseen. Read from code; tiny window.
10. brief_gate refuses any brief containing "time-box" or "whole task", including an owner quote or rule text that mentions them (loud, not silent). Low.
