## 0. Headline findings for the main session
1. Street lights are NOT new work in sim_core. `sim_core/include/cp/street_lights.h` + `Wrap_street_lights.cpp` already exist (runs, junction corners, roundabout ring and island, central-reservation twin arms, bridge parapet). Unreal draws none of it (render layers today: ground, ground skirt, road surface, markings). So M6 is mostly: data audit against sources and photos, then `FCPInstanceLayer` + kit mesh import, plus tests.
2. The UK light values in `data/regions/uk/road_types.json` say about themselves: "estimate: ... BS 5489 style values recalled, not checked ... tuned by eye" (line 8). This research checks them (section 2). Mismatches: main_street outreach 1.2 m on an 8 m column (council spec caps 8 m columns at 1.0 m); `a_road_dual` uses `central_reservation` twin 12 m columns, but all three dual photos opened (street/31, 110, 111) have columns on the OUTER verges and none in the median.
3. BS 5489-1:2020 itself was readable (a licensed copy hosted by Lincolnshire County Council, marked "Not for resale"; I paraphrased only, no long quotes). TD 501 (Mar 2020, now marked SUPERSEDED) and CD 109 contain NO column set-back, spacing or height numbers: they point to BS 5489 and BS EN 13201 and to NG 1302 / BD 26/04 (structural design). Do not cite them for geometry.
4. No UK written source gives column SPACING as a number: spacing is a photometric result (BS EN 13201-3 calculation per luminaire). The only honest sources for spacing are photos (count and measure) and local specs that say "to suit design". The repo spacings (30/35/32/28/50 m) stay "photo-derived, not written", to be measured in the M6 round.
5. Photo index error to fix: street/31 is captioned "from the grass central reservation ... lamp columns"; the columns in it stand in the OUTER verges (tall black column right, thin column left at the fence), not in the median.

## 1. What exists in the repo today (<= 25 lines)
- `sim_core/include/cp/vegetation.h` + `src/vegetation.cpp` (2886 lines). Two sources: `world_cover` (the existing world's cover, a pure function of position and world seed behind the replaceable `WorldCoverSource` interface: ground cover, woodland, scattered trees, hedgerow field boundaries; r4 added fields with `LandUse`, tint, row direction on `CoverGround`) and `vegetation` (road-edge scatter generated by the road: verge strips, creep over hard strips, scrub, dual central-reservation grass, optional street trees, island planting).
- Shared `veg_corridor` mask: road cross-sections + verge, junction polygons, roundabout islands, hook for the graded-earthworks footprint; clear() is 0 inside, smoothstep to 1 over `blend_band_m`; tall things also barred from junction visibility triangles. This is what makes "a road clears vegetation".
- Types: `VegInstance`, `VegInstanceGroup`, `HedgeRun`, `GrassStrip`, `GroundPatch(Group)`, `AreaPlanting`, `VegetationTile`, `VegTypeDef`, `VergeRule`, `StreetTreeRule`, `IslandRule`, `WorldCoverRules`, `VegetationRules` (parsed from the `vegetation` block of region.json, `parse_vegetation_rules` / `load_vegetation_rules`), `CoverGround`, `CoverPoint`, `CoverLine`, `WorldCoverSource`, `LandClass`, `LandUse`.
- Incremental == full invariant (exact equality) with conservative widening by `VegetationRules::reach()`; street-light phase is read for street-tree clearance via pure function `generate_edge_street_lights` (documented limit: roads >= 15 m apart). Slowest test in the suite is "vegetation: incremental update equals a full rebuild" (70 s; speed follow-up in QUEUE).
- Layers registered by `cp::add_vegetation_layers(cache, rules, VegetationParams)`; Unreal: `CPSimWorld.cpp` loads the rules and registers them when `UCPSettings::bRegisterVegetationLayers` (default true) but comments say "not rendered yet". `Wrap_vegetation.cpp` and `Wrap_street_lights.cpp` exist in the plugin.
- `world_cache.h`: layer `street_lights` (`kLayerStreetLights`, tile_data `StreetLightGroup`, `rebuild_dirty_street_lights` widens one graph hop). `StreetLight` carries position (world doubles), heading, mounting_height, outreach, style (mesh id), edge, node, s, side, origin, on_structure, twin_arm, partner_edge.
- `RoadType.street_lights` (`StreetLightRules`: lit, spacing, arrangement SingleSide|Staggered|Opposite|CentralReservation, setback, footway_inset, mounting_height, outreach, style, island_min_radius). UK values now: residential 6 m / 0.6 outreach / 30 m / single_side / setback 0.8; b_road 10 m / 1.5 / 35 m / staggered / 1.0; main_street 8 m / 1.2 / 32 m / staggered / 0.8; roundabout_ring 8 m / 1.0 / 28 m / single_side / island_min_radius 10; a_road_dual 12 m twin / 1.8 / 50 m / central_reservation / 1.5; motorway unlit; a_road_rural, b_road_rural, country_lane `lit:false`.
- Geometry knobs in `StreetLightParams` (junction_offset 3.0, carriageway_clearance 0.5, corner_clearance 1.0, crossing zones, island_clearance 1.5, min_corner_angle 0.8 rad, bend_outside_radius 150 m, median_slack 3.0, parapet_inset 0.3).
- Unreal render: `ICPRenderLayer` registry, layers Ground, GroundSkirt, RoadSurface, Markings. NO instance layer, no ISM pool, no kit import. Game plan M6 row: "Wire `ground_height` and `grading_footprint`" into the corridor mask; `FCPInstanceLayer`, kit import; verified by instance-count test and renders; spike: add and remove 50k ISM instances per tile swap and time it.
- Free meshes on disk, uncommitted: `unreal/CityPainter/SourceArt/Meshes/Free/{Mantissa,PolyHaven,ambientCG}` (trees, grass, shrubs); no lamp column asset chosen yet (the kit scripted Blender meshes in `tools/blender_kit/` and the stopped vegetation kit are the other sources; check `docs/research/free-assets-roads-world.md` for a free column).
- Open decisions in docs: HANDOFF says the starting world holds nothing man-made; M6 order is after M5 (GAME order M2 -> M3 -> M5 -> M6 -> M7). Vegetation scripted kit is stopped; real trees via the `pvetrees` verdict (not started).
