# Agent contract (every builder and reviewer agent follows this; the main session pastes it unchanged into every brief)

AGENT-CONTRACT-MARKER: v1

The photo is the target. The list of faults in your brief is a starting list, not the task.

1. **Open the references first.** Before designing, open at least 3 reference photos per case (top-down for layout) from `C:\Users\bgbg0\Documents\Programming\roadworld\docs\reference\` (the main checkout; run `powershell -NoProfile -ExecutionPolicy Bypass -File tools\new_agent_worktree.ps1 <name>` or link the folder, your worktree has none). Name every file you opened. Measure in lane widths. If no photo covers a case, say so and fetch one. A score or claim resting on fewer than 2 opened photos per view must say so. **Every file the brief names as a reference or spec (photos, prototype screenshots, spec documents, earlier STATUS files) is opened, all of them, no sampling.** STATUS.md carries `References opened: N of M listed` plus the file names; if N < M, list the unopened ones under "Skipped, refused or failed" as "not opened" with the reason. N < M with no reason is sent back.
2. **Downloads of reference photos are pre-approved by the owner.** The owner's words (11 Oct, in chat): "If you ever need more reference images go get them" and "yes please allow them to download photos as and when needed". Save them into `docs/reference/{aerial,street,gsv}/` and log source URL and content in the reference INDEX. This covers reference images only: assets, models, textures, tools and anything paid need the owner.
3. **Reference photos are private.** Never commit them or copy them anywhere outside `docs/reference/`. Side-by-side composites go in `docs/reference/_compare/<topic>/` (gitignored); the committed `COMPARE.md` lists names and verdicts only. You may delete your own composites with `rm -rf <main checkout>/docs/reference/_compare/<your topic>` (the delete guard allows exactly that and nothing else under docs/reference).
4. **Self-audit before anyone else does.** The finish line is the photo, not the item list. Render at the framing of the best photo, build a composite (render | photo | before, same camera), write your own fault list in `FAULTS.md` answering "what would a driver, engineer or reviewer say is wrong or would never be built?", fix it, re-render. Up to 3 passes. Include faults that are not in the brief. An empty fault list is suspect. Open every render yourself before saying it is fixed, good or done; name the image that carries each claim.
5. **Never mark an item "not done" without having tried it.** Say what blocked it. Stop when the residual list holds only things you cannot fix, or after 3 passes.
6. **Skipped, refused, failed or unverified items go in the FIRST lines of your report and under the first heading of `STATUS.md`.** Nothing fails silently.
7. **Hand in** the files named in the brief (see `docs/templates/STATUS.md`), then run `node tools/check_handin.mjs <progress-folder>` and fix what it reports.
8. **Work in your own git worktree and branch**, with ONE build dir (`<worktree>\build`, no other `build-*` dirs; scratch goes to `..\roadworld-scratch\<slug>`) and CLEAN builds. Commit after every verified step. Every tool call of an agent starts in the MAIN checkout (the cwd is reset between calls): run git as `git -C <absolute path of your worktree> ...`. For every subagent (the main session is not limited), `git add -A`, `git add .`, `git commit -a` and `git stash -u` in the main checkout are refused (git_guard hook). Every other git write in the main checkout is refused only for a builder launched with a HANDIN_DIR: `git branch` with a name, -d, -D, -m, -M, -c, -C, -f, -u or --track; `git tag` with a name, -a, -f, -s, -u or -d; `git gc`; the `git worktree` forms add, remove, prune, move, lock, unlock and repair (list and the rest are read-only); and the other write subcommands (commit, merge, reset, push and so on). NO-CONTRACT clerks and mergers may commit in main with explicit paths. Read-only forms (status, log, diff, show, stash list, branch --list, tag -l) stay allowed. Never delete a worktree or any folder that may hold a junction with `rm -r`, `rm -rf`, `Remove-Item -Recurse` or any recursive delete: `docs\reference` in every worktree is a junction to the private photos in the main checkout, and a recursive delete follows it (22 Oct 2026 this wiped every reference photo); remove a worktree only by first running `cmd /c rmdir <worktree>\docs\reference` (removes the link only), checking the main checkout's `docs\reference` still has its files, then `git worktree remove`.
9. **Never kill processes you did not start** (compilers, Unreal, other agents). Unreal is a single lane: one editor or plugin build at a time.
10. **Never ask the owner to open Unreal or playtest.** You launch, drive, screenshot and close it yourself.
11. **Mute any video** you play in a browser. The owner hears it.
12. **Every push and commit message carries `[skip ci]`.** Run slow commands (builds, pushes) in the background.
13. **The browser prototype (`prototypes/road-draw`) is the UI spec** for the game. Prefer free tools and assets; flag any cost.
14. **Research Unreal, plugin and tool facts from source (`C:\UE_5.8`) or docs, never from memory.**
15. **Photos outrank tests, audits and fault lists.** If a test, an earlier audit or the brief's fault list disagrees with what the matched photos show, the photos win: say so in STATUS.md and change the test. A test whose expected value has no photo measurement or written rule (for example `docs/road-marking-rules.md`) behind it may be rewritten or deleted; say which and what it pinned. Rebuild a shape from measurements rather than tuning one that did not come from a photo. Never change the design to suit the renderer: fix the view.
16. **Builder and auditor are never the same agent.** If you build, an independent auditor follows your hand-in and you do not audit your own round; do not audit other agents' work unless your brief carries the marker line AUDIT-OF (an auditor brief from `make_brief.mjs --audit`). An auditor writes its own fault list before opening the builder's FAULTS.md or STATUS.md, checks the builder's measuring tools (tests, section sheets, diagnostic views, playtest scripts) against the data, and writes `AUDIT.md` (first lines: `Auditor agent: <your agent id>`, `Verdict: accept | send back`, `References opened: N of M`; template `docs/templates/AUDIT.md`); the finish gate refuses it without that file or with the builder's id.

17. **Audits are strict and every audit item gets fixed** (owner, 22 Oct, in chat: "when you audit, be strict and ensure EVERYTHING gets addressed in a fix. no excuses for not fixing issues unless its like so pedantic i wouldn't notice or you aren't sure the audit is picking things up right"). Auditors list every fault they see under "For the next builder" in AUDIT.md; none is softened or dropped as minor unless it is too small for the owner to notice. The next builder fixes EVERY item from the prior AUDIT.md and its own FAULTS.md. An item may stay open only for (a) too pedantic for the owner to notice, or (b) the audit's measurement or reading is doubtful, shown by the builder's own check (picture, measurement, numbers); each open item is written in STATUS.md under the first heading with that evidence. "Out of scope", "time", "would need a bigger change" and "later round" are not reasons. STATUS.md carries a table "Prior audit items": item | fixed (image or test that proves it) or open (reason a or b plus evidence). The next auditor checks every earlier audit item against that table and re-opens any item not truly fixed.
18. **Audits start with a first look, then an outline overlay, then measuring** (owner, 22 Oct, in chat: "I'm more concerned the auditor didn't pick up on what id say is the most obvious visual error"). Before any measuring, view the whole junction or site top-down plus a driver's-eye view beside the matched photo at normal size, and write the 3 most obvious faults, ranked by how fast a passer-by would notice them; the most obvious one is the first line of AUDIT.md's fault list. Then trace the render's kerb, edge and island outlines over the photo at the same scale and rotation; every shape difference is explained or listed as a fault. Only then measure item by item. Auditor briefs carry the task file's cases, not an itemised checklist (it anchors the auditor).
19. **Engineering decisions go in the FIRST brief** (main-session decision, 23 Oct 2026, after the owner asked why rounds take so long). The main session makes the road-engineering calls from the photos before round 1 of a feature (structure choice, corner rules, wall versus slope, limits). Builders implement them; a builder that finds one wrong writes why with a photo measurement in STATUS.md and does not silently choose otherwise.
20. **One case per round.** A round brings one case to "matches the photo" before the next case starts, so every audit item can be fixed.
21. **Shape and look are accepted apart.** Geometry from the sim_core viewer is accepted on the outline overlay and measurements; look (texture, detail, materials) is judged in Unreal. Viewer look faults the viewer cannot render are not send-back reasons.
22. **No goalpost moves.** Never raise a test limit, add a per-case limit or exclude an area to make a test pass. Fix the geometry, or write BLOCKED.
23. **Locked tests.** A test the auditor wrote is locked: any file under `tests/locked/`, or named in `LOCKED_TESTS.txt` in the prior round's hand-in folder (the folder of the brief's `PRIOR-AUDIT:` file). The auditor writes that list as UTF-8 or UTF-16, one path or glob per line, beside its AUDIT.md. A builder may not edit, delete, rename or reformat a locked test, nor edit `LOCKED_TESTS.txt` or the prior AUDIT.md (the lock_guard hook refuses Write, Edit, shell writes, in-place formatters and inline python or node writes; reading is free; paths built from variables or `$(...)` cannot be seen by the hook and are still forbidden). Make the test pass, or write `BLOCKED: <item> | tried: | blocked by:` in STATUS.md.
24. **Checkpoint.** You may stop early once per round with `<HANDIN_DIR>/CHECKPOINT.md`, first line `CHECKPOINT: <what is done> | images: <path>[, <path>...]`, naming at least one image that you wrote during this run, in the hand-in folder or its `_compare/<round>` folder, a real PNG or JPEG of 10 KB or more; `node tools/check_handin.mjs <folder> --checkpoint` checks it. The finish hook lets it through once per round (30 s window for the two hook calls of one finish); it is NOT a hand-in and starts no audit. DELETE CHECKPOINT.md before your final hand-in: a CHECKPOINT.md older than your latest commit is ignored, and a second checkpoint in the same round gets the full check. The image check is a floor (location, age, size, header); the main session's own look at the image is the real check.
25. **Speed rules (main session, 23 Oct 2026, after the owner said "these are some slow agents!!").** Compiler: while working, build and test with gcc only; run the MSVC suite once, on the final state, before hand-in. Build mode: use incremental builds while iterating; run ONE clean build (sim_core, and Unreal if the round touches it) on the final state before hand-in (item 8's "CLEAN builds" means that final build). Self-audit renders: a self-audit pass re-renders only the views whose inputs changed; run the full composite set once, at the end. Commits: commit after each verified step, as item 8 says, so progress is visible.
26. **Time limits on every run.** Wrap every build, test, render or playtest command in a time limit (for example `timeout 900 <cmd>`; 15 minutes at most for a full suite, 10 for anything else). Never start a second copy of a run that is still going. A run that hits its limit is a finding: find the slow or hung case with filters (`-tc`, `--durations`) and fix it, or write it in STATUS first lines; never wait on it. Main session, 23 Oct 2026: two agents waited over an hour on hung test runs (one profile test ran 5.5 hours).
